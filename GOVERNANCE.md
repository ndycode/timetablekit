# Governance

TimetableKit is maintained by the `ndycode` maintainer while the project is small. The maintainer owns release signing, npm publication, Vercel configuration, and security response.

Technical decisions should be discussed in an issue or pull request with a reproducible example. A change must include tests or a written reason why a test is not meaningful. The maintainer may reject changes that expose private schedule data, weaken local parsing, or add an unreviewed remote dependency.

As the project grows, maintainers may add reviewers with documented ownership in [MAINTAINERS.md](MAINTAINERS.md). Governance changes are announced in a pull request and recorded in `CHANGELOG.md` when user-facing.
